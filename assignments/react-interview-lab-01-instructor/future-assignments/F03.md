# F03 — Fresh information without lost work

## Candidate handout (release only when selected)

Operators keep RelayOps open for long shifts. Add a controlled policy that keeps the queue reasonably fresh while protecting work in progress. Choose and explain an interval, focus-based strategy or another explicit policy. Show when the last successful synchronization occurred and whether information may be stale.

Acceptance: avoid overlapping unnecessary reads; clean up timers/listeners on unmount or policy changes; do not poll hidden tabs without reason; preserve unsaved notes; reconcile confirmed mutations with incoming snapshots. A failed refresh should retain usable data and show recoverable feedback. Manual refresh remains useful. Define when selected-ticket details and team summaries refresh too.

Existing architecture: useQueue owns list loading/cache, App owns summary and selection, TicketDetail owns a note draft. Scope 45–60 minutes. Begin with a coherent ownership model and a small refresh policy. Test with fake timers or controlled promises: teardown, hidden-tab behavior, failed refresh, unsaved note during server updates and both GET/PATCH completion orders. Avoid wall-clock sleeps in unit tests.

Edge cases: team switch while reading, multiple tab focus events, mutation failure, changed remote note, reset from another browser and a component remount. Optional extensions: manual conflict resolution, backoff, revision-based conditional requests or cross-tab refresh coordination.

## Examiner notes — never release

Use after C and D are understood; otherwise the task can become their integration exercise. Hints should distinguish draft from server state, request cancellation from response acceptance, and freshness from loading. Trade-offs include polling cost, stale-while-revalidate display, strict versioning and a query library's ownership model. Do not accept a timer that captures an old query, never cleans up or triggers a new request per render. Do not require real-time transport or sophisticated conflict-free merging.
