# F04 — Investigate a slow queue overview

## Candidate handout (release only when selected)

A proposed queue overview becomes noticeably slower when the support dataset grows. You will receive a performance scenario on a separate branch. Investigate with React Profiler and browser performance tools; identify where work occurs and which user interactions cause it. Measure a before/after improvement, keeping the displayed result correct.

Acceptance: establish a reproducible interaction and dataset size; record hardware/browser and measurement method; reduce major unnecessary work; verify query changes still produce correct results. Evaluate memoization, computation structure and how many DOM rows should be present. Explain whether pagination or virtualization is appropriate. Avoid blanket memoization before profiling.

Existing architecture: the scenario adds an overview using a larger deterministic fixture set alongside the existing queue. Scope is one focused performance change in about 45 minutes; no production-scale backend redesign. Test result correctness against small fixtures and integration of search. Measure initial render and typing separately; avoid asserting milliseconds in CI.

Edge cases: no matches, broad and narrow searches, repeated queries, team switching and slow CPUs. Optional extensions: background computation, incremental indexing, or an API-backed aggregate with documented freshness semantics.
