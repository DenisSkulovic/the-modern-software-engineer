# F02 — Bulk ticket assignment

## Candidate handout (release only when selected)

Team leads need to select several visible tickets and assign them to an operator in one action. Add row checkboxes, a select-all-visible control, selection count, a bulk action bar and an appropriate HTTP endpoint. Make progress and outcomes clear without blocking the whole workspace unnecessarily.

Acceptance: operator choices respect team membership; the API validates every item and reports per-ticket successes and failures. A valid ticket still succeeds when another item fails. After completion, confirmed assignments and summary data are coherent; failed items remain identifiable and retryable. Define selection across pages, filters and team changes. Prevent accidental duplicate submission.

Existing architecture: the server Store updates individual tickets and adds activity; App applies confirmed entities via useQueue.replace. Scope is one bulk endpoint plus UI and integration, 45–60 minutes. No background job service is needed. Test all-success, partial success, invalid IDs, foreign-team assignees, a failed network call and selection changes during a pending operation. Ensure keyboard users can identify each checkbox and the indeterminate select-all state.

Edge cases: duplicate IDs, empty or oversized selection, records changing teams between selection and submit, a retry after partial completion, and refresh overlapping the mutation. Optional extensions: select all matching results using an explicit query contract, or undo with a documented concurrency policy.

## Examiner notes — never release

Business semantics first: partial success versus atomic transaction. Require bounded input (for example 100 unique IDs) and meaningful per-item errors; do not demand a specific status code if the contract is clear. Hint toward canonical server validation rather than trusting client selection. Watch for Promise.all rejecting away successful outcomes and stale refreshes replacing confirmations. Sequential requests can be a valid first slice if limitations are stated; the requested endpoint is the target. Judge correctness and feedback over optimistic UI sophistication.
