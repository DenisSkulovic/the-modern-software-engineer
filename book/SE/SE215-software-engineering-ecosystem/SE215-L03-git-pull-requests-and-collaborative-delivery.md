### Learning Objective

Understand the collaboration and release consequences of common Git workflows.

### Opening Problem

Three engineers develop features simultaneously. One urgent production fix must ship while two unfinished features remain in progress. The team's branching and release strategy determines whether delivery is straightforward or chaotic.

### Planned Coverage

Git as a distributed version-control system; commits, branches, merges, rebases, cherry-picks, conflicts, trunk-based development, feature branching, pull requests, branch protection, code-review etiquette, commit hygiene, release tags, and feature flags. Trade-offs between merge commits, rebasing, and squash merges. Why small changes are easier to review and release, and how Git workflows interact with CI/CD.

### Scope Boundaries

Not a beginner command-by-command Git tutorial. Assume familiarity with basic add, commit, push, pull, and branching.

### Expected Understanding

Choose a sensible branching/review strategy for a team, explain trade-offs, and handle common collaborative development scenarios.

### Suggested Exercise / Lab

Design a safe workflow for an urgent hotfix while multiple incomplete features exist.
