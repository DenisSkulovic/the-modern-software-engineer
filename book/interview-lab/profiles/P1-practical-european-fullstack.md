# P1 — Practical European product-company full-stack

**Status:** default preset  
**Use when:** No stronger company-specific evidence; product engineering roles in Europe — especially Germany, the Netherlands, Sweden, and similar markets (DACH, Benelux, Nordics, and comparable EU product companies).

## Snapshot

| Field | Default |
| --- | --- |
| Market | Europe — Germany / Netherlands / Sweden or similar (name a country when known) |
| Company type | Product startup, scale-up, or product company |
| Role | Full-stack or backend-leaning full-stack |
| Seniority | Mid → senior (match the JD) |
| Interview language | Usually English unless the JD/invitation says otherwise |
| Algorithm-heavy | **No** unless invitation/JD says otherwise |

## Likely preparation areas

- Work history and actual technical contributions
- Node.js / TypeScript; frontend–backend collaboration
- Database choices; asynchronous behavior; debugging
- API architecture; code maintainability; production judgment
- Practical technical discussion; possible live coding, pair session, or take-home when indicated
- Logistics that often matter in EU hiring: relocation/remote policy, notice period, right-to-work / visa when relevant, language expectations — only when the round is HR/recruiter or the JD raises them

## Do not automatically include

- FAANG-style multi-round LeetCode gauntlets
- Planetary-scale system design for ordinary senior FS roles
- Rehearsed corporate behavioral slogans
- **Israeli / Tel Aviv market conventions** as if they were the target (they are not)
- National caricatures (“German interviews are always X”) — company and interviewer matter more

## Evidence note

Individual Glassdoor / Blind / Levels-style reports are **anecdotal**. Label them as such. Prefer invitation + JD when available. Country is a weak prior; the employer’s process wins.
